# مشکلاتِ باقی‌مانده و چیزهایی که از مالک لازم است

## نیازمندی‌های مالک (مسدودکنندهٔ انتشارِ درآمدزایی)
1. **حسابِ توسعه‌دهندهٔ مایکت** → کلیدِ RSA + ساختِ ۸ محصول (جدولِ 13_MYKET_GUIDE.md). بدونِ کلید، پرداخت عمداً خاموش است.
2. **حسابِ ناشرِ تپسل** → zone واقعی؛ الان zoneِ آزمایشیِ رسمیِ خودِ تپسل در بیلد است (`TAPSELL_ZONE_IS_TEST=true`) — درآمدِ واقعی نمی‌دهد.
3. **سرور + دامنه + PostgreSQL + HTTPS** → `SERVER_URL`. تا پیش از آن مونتیزیشنِ ابری (خرید/جایزه/VIP ابری) خاموش و بازی کاملِ آفلاین است.
4. **تأییدِ تستِ روی دستگاهِ واقعی** — نصب/خرید/تبلیغ روی گوشی باید توسطِ مالک انجام و در TEST_REPORT ثبت شود (در این محیط adb/دستگاه نیست).

## محدودیت‌های فنیِ مستندشده
- تأییدِ پاداشِ تبلیغ بدونِ S2S تپسل است؛ امنیتِ کافی برای نسخهٔ اول (سقفِ سرور + adRef یکتا + onRewarded) ولی توصیه: بعد از راه‌اندازی، S2S تپسل اضافه شود (`ad_sessions` آماده است).
- «دوبرابرِ درآمدِ روز» به درآمدِ گزارش‌شدهٔ کلاینت وابسته است — سرور آن را با سقفِ ۴۰۰ سکه و سقفِ درآمدِ ۲۰۰ کپ می‌کند (ضدِ جعلِ عددِ درآمد).
- کالاهای ظاهری (پوستهٔ starter_bundle) سمتِ کلاینت اعمال می‌شوند؛ ثبتِ تراکنش سرور است — سرقتِ آن معادلِ سرقتِ cosmetic است، نه ارز.
- اشتراکِ VIP: پس از انقضا، تمدید دستی/بازیابیِ خرید لازم است (auto-renew مایکت تا حدِ امکان پشتیبانی می‌شود؛ کالیبراسیونِ نهایی پس از حسابِ واقعی).
- آپدیت‌کنندهٔ HTMLِ درونِ APK قبلی بدونِ اجازهٔ INTERNET هرگز کار نمی‌کرد (یافتهٔ ممیزی) — در نسخهٔ Kotlin اجازه داده شد؛ رفتارِ پیش‌فرضِ آپدیت در بیلدِ Kotlin فعلی خاموش است تا `SERVER_URL`/دامنهٔ توزیعِ HTML مشخص شود (design decision؛ در TEST_REPORT پیگیری می‌شود).
